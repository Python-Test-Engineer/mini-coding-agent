What the console and audit log see

    Who owns what?

    Agent: owns the loop and calls UI methods such as show_tool(), show_result(), and show_done(). It keeps no print() of its own.

    Brain: src/brain.py holds the system prompt and tool schemas and makes the provider request; it is the only module that talks to a model.

    Tools: src/tools.py holds the four tool functions; bind_tools() attaches the workspace or runner the loop is using.

    Hooks: observe lifecycle boundaries. The default SandboxAuditHooks adds sandbox audit records; hooks do not enforce path policy and do not print.

    Sandbox: enforces file and command rules where operations execute. A blocked write asks the UI for the red [FORBIDDEN] banner (UI.show_forbidden(), wording from ui.json), plays the Windows alert when available, then raises a fatal error.

    There is no separate UI event bus here: the host calls UI methods directly. The UI formats those calls using src/ui.json.

    Session hooks wrap the interactive conversation; turn hooks wrap each request. The JSONL audit trail is written under logs/. This local runner constrains tool behavior but is not an operating-system security sandbox. See the detailed flow reference or explore the feature animations: logging, hooks, sandbox, and UI.
