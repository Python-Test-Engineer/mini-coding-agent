Chapter 01 / Agent foundations

A coding agent
is a loop.

A model proposes the next action. Python executes it, returns the result, and asks the model what to do next.

01Separate model decisions from host execution.

01 / MODEL
The central idea

Decide. Execute. Feed back.

The model does not run Python functions. It returns a proposal; the host program decides which registered tool to call and sends the result back in the next request.

02 / TOOLS
The host's capabilities

Four functions. One small toolbox.

An agent can only do what its host exposes. The tool registry in agent.py maps the model's requested name to a Python function.

ToolWhat the host does
write_file(path, content)Writes text to a file under the working directory by default.
edit_file(path, old, new)Replaces the first matching occurrence in a file.
read_file(path)Reads a file and returns its text.
run(command)Runs a shell command with root work/ as its current directory.
Important · not a sandbox

The agent always uses the repository-root work/ directory, even if launched from src/. But file paths are not contained there, and run() uses shell=True. Commands run with the user's permissions. Use trusted prompts only.

03 / HANDOFF
Who does what?

The model asks. The host acts.

Tool schemas advertise available functions in the chat request. A schema is an interface description—not permission for the model to execute code on its own.

  1. Describe toolsThe request includes JSON schemas: names, arguments, and required fields.
  2. Receive a proposalThe assistant response names a tool and provides JSON arguments.
  3. Dispatch in PythonThe host decodes arguments and calls the matching function in TOOLS.
  4. Return the resultThe host adds a role: "tool" message with the matching call ID.
OpenAI-compatible schemawrite_file
{
  "type": "function",
  "function": {
    "name": "write_file",
    "parameters": {
      "type": "object",
      "properties": {
        "path": { "type": "string" },
        "content": { "type": "string" }
      },
      "required": ["path", "content"]
    }
  }
}
04 / HISTORY
The loop's working memory

Every turn is sent again.

The chat API is stateless. The agent keeps the conversation in a Python list and resends that history with each request, including assistant tool calls and host results.

01 · START

System + user

The instructions and request form the first message history.

02 · PROPOSE

Assistant tool call

The model asks for a tool and gives it a unique call ID.

03 · EXECUTE

Host runs function

The Python process executes the registered function and captures a result.

04 · REPLY

Tool message

The result is added with tool_call_id so it matches the request.

05 · REPEAT

Send history again

The model sees what happened and can request another action.

06 · FINISH

No more tools

A response without tool calls ends the loop; eight steps is the maximum.

assistant
tool call: write_file(...), ID call_01
tool
tool_call_id: call_01 · Created hello.py
assistant
final answer with no tool_calls · the loop ends
05 / CONFIG
The API boundary

Plain HTTP, explicit inputs.

The project uses Python's standard library for JSON and HTTP. The request goes to OpenRouter's OpenAI-compatible chat-completions endpoint.

API key
OPENROUTER_API_KEY environment variable, then the matching line in root OPENROUTER.txt.
Model
MODEL environment variable, then root OPENROUTER.txt, then deepseek/deepseek-v4.1-flash.
Endpoint
https://openrouter.ai/api/v1/chat/completions
Working files
Root-level work/, anchored from src/agent.py so launch location does not change it.
UI wording
src/ui.json supplies the labels and Rich styles used by src/ui.py.
06 / OUTPUT
What the user sees

Rich makes the loop legible.

UI renders the request, model text, tool calls, code, results, and final status. The footer is wired to usage data returned by the API.

CONTEXT ESTIMATELatest prompt_tokens. A percentage appears only if the response includes context_limit.
TOTAL TOKENSPrompt and completion tokens accumulated over model calls.
COST SO FARSum of response cost values when the provider supplies them.

If a provider omits usage fields, the app keeps the last available values. Tests use fixed responses and do not need a live API key.

07 / TRY IT
Run the demo

Watch a request become work.

Set an OpenRouter key, launch the agent from src/, then watch the model's proposed actions and the host's results.

Run the coding agent

From the repository root in PowerShell. Generated files still go to root work/.

$env:OPENROUTER_API_KEY = "your-key"
cd src
uv run agent.py "write a hello world script and run it"

Run the test suite

These standard-library tests stub the network boundary; they make no OpenRouter request.

uv run python -m unittest discover -s tests -v
